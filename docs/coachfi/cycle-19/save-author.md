# C19 — autor adaptera zapisu quizu

Nowy lib/quiz-learning-save.ts jest małym adapterem faz nagrody nad niezmienionym createReviewSaveController. Nie powiela walidatora SRS, blokady inFlight, ticketów lub quarantine. Root jest autorem QuizCard i jedynego callera app/quiz; ich niezależny static consumer review jest osobnym dowodem i nie przyjmuje tego helpera.

Przed źródłami zapisano pełny before siedmiu powiązanych plików i kontrakt. UI reviewer odtworzył actual QuizCard baseline 3PASS/7FAIL na starym146cd57d…, m.in. zastąpienie uszkodzonej historii, lying SRS ACK i ponowienie częściowej nagrody przez zmianę widoku. To odrębny baseline, nie własne powtórzenie autora. Wspólne review-save, quiz-save, SRS, tokens i StreakContext pozostały literalnie niezmienione.

Preflight nagrody odbywa się dopiero wewnątrz istniejącej admission, przed SRS. Istniejące canAwardTokens/getTokenBalance weryfikują jeden uchwycony snapshot tokenów, zachowując125 przy braku klucza, Math.round i bezpieczny zakres. Invalid/read-denied/overflow przed zapisem daje retryable z reason token-validation; owner loss zachowuje pierwszeństwo stopped/ignored. Wrong answer lub brak descriptoru nie waliduje dodatkowo wartości salda i nie wywołuje award/activity.

Po potwierdzonym SRS sprawdzamy brak driftu salda, wywołujemy award na tym samym traced handle i wymagamy synchronicznego receipt oraz dokładnego raw oczekiwanej nagrody. Dopiero potem działa activity. Końcowe saldo musi być kanoniczne i co najmniej potwierdzoną kwotą; legalny bonus streak może je zwiększyć. No-op award nie może zostać ukryty większym bonusem, bo activity nie zostanie wcześniej wywołane. Null jest dozwolony jedynie dla pierwotnego braku klucza i delta0; usunięcie istniejącego salda nie może wymyślić125. Zwracamy balance wyłącznie wraz z saved. Żaden błąd po SRS nie jest zwykłym retry lub udawanym rollbackiem.

Actual parent używa rozdzielonego bundle award/activity/confirmed. Confirmed pozostaje poza helperem i publikuje parent UI dopiero po saved oraz wycofaniu starego ticketu. Legacy onReward(amount) zachowuje pojedynczy argument, ale sam callback call nie jest dowodem nagrody; musi przejść tę samą walidację receipt. Callback legacy łączący nagrodę i bonus bez faz może zostać zachowawczo odrzucony. Actual jedyny parent korzysta z bundle.

Pierwszy i jedyny własny targeted run:34/34PASS, exit0, dziewięć fingerprintów przed/po bez zmian. Uruchamiano rzeczywiste recordAnswer, addTokens, markActiveToday i reachedMilestone na syntetycznym RAM. Callback milestone odtwarza istniejący mnożnik5 z kontekstu; nie jest to mounted StreakProvider test. Mockowane były cloud/persist/events, a fetch trap potwierdził brak sieci. Sprawdzono nowe fazy, no-op+bonus masking, legalne15/35, strict preflight, częściowe/lying/asynchroniczne award, drift, zerową nagrodę i rounding, końcowy SRS ACK, utratę właściciela i reentry przy zmianie języka w token evencie. Nie powtarzano zielonych C18 guard/parser cases ani aggregate/TS/Chrome/build. Surowy wynik: save-author-tests.json; command/stdout i fingerprinty: save-author-run.json.

Autor nie zatwierdza własnego helpera. Jego finalne przyjęcie należy do daily_data_review; actual komponent/parent/E2E do odrębnej ścieżki UI i roota. Raporty autora mają status przygotowanego kodu z lokalnymi testami, dopóki niezależne bramki nie zostaną zapisane.

Ograniczenia: RAM modułu, bez journal/CAS/rollback/durable exactly-once po reload lub między kartami. Partial SRS/reward/streak może pozostać zapisany po uncertainty. Readback potwierdza obserwowane lokalne bajty, nie chmurę i nie późniejszą trwałość. Brak nowych pól, zmian ekonomii, produkcyjnych zapisów, AI/cloud activation, commit/push/deploy lub dowodu staging/CI/Auth/RLS/produkcji. Odroczony draft finansowy pozostaje niewdrożony.
