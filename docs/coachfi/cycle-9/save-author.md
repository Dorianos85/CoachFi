## Kontrakt potwierdzony przez koordynatora

`readDailyChallengeState(storage)` zwraca `available`, `completed` albo `unavailable`. Odczyt wymaga bieżącego handle i browser context. Brak klucza jest dostępny; istniejący marker musi być obiektem JSON z jedynym własnym polem `date`, rzeczywistą datą YYYY-MM-DD. Zachowano dotychczasową datę UTC: dziś ukończone, przeszłość dostępna, przyszłość lub nieznane/nieprawidłowe bajty niedostępne. Nie zmienia się dat, nie naprawia ani nie nadpisuje markera.

`createChallengeSaveController()` ma `version`, `reset`, `isOpen(ticket)` oraz `run(ticket, storage, command, activity?)`. Command zawiera niepuste string questionId, answer IDs A–D i nieujemny safe integer reward. Result jest frozen: `saved`, `wrong`, `completed`, `retryable`, `uncertain`, `stopped` albo `ignored`; `earned` występuje wyłącznie przy saved. Wrong/completed/saved zamykają bieżący ticket. IsOpen jest czystą kontrolą epoch i stanu committed/blocked/inFlight bez odczytów storage. UI ma resetować kontroler wyłącznie przy owner change lub unmount; locale change nie usuwa quarantine.

Correct przechodzi strict marker read i token preflight przed mutacją, potem rzeczywiste `addTokens` na traced handle. Natychmiastowy canonical token read musi odpowiadać saldu zwróconemu przez addTokens; dla reward0 zachowuje przedmutacyjne bajty, w tym brak klucza. Następnie `markChallengeCompleted` na tym samym handle oraz synchroniczne activity. Końcowe odczyty potwierdzają marker oraz canonical saldo nie mniejsze od potwierdzonego reward balance. Istniejąca activity może legalnie dodać bonus serii dni; nie może usunąć, uszkodzić ani obniżyć salda poniżej potwierdzonej nagrody. Wrong nie czyta punktów, nie zapisuje markera i nie wywołuje activity. Today completed blokuje przed odczytem command lub reward.

Każde wywołanie traced setItem/removeItem oznacza próbę mutacji przed delegacją. False, throw, write-then-throw i późniejszy błąd przy udowodnionym bieżącym ownerze dają uncertain, blokujący ticket bez replay/rollback. Sticky read fault blokuje następny writer. Bez próby mutacji błąd daje retryable. Utrata epoch/owner lub nieudowodniony current daje stopped. In-flight chroni reentry także po reset do finally. Callback zwracający thenable nie dostaje saved; tylko native promise rejection jest obserwowany, bez await/replay. Retired trace blokuje późne użycie storage.
