# PR #19: dependency patches and bounded Chromium installation

This package updates Vitest 4.1.11 to 4.1.12 and Next.js 15.5.27 to 15.5.28, and separates the browser installer into bounded dependency and headless-shell phases. It prepares the existing PR for CI; it does not enable deployment or establish production readiness.

## Problem and implementation

The published d1f4eb0 recovery run 39771851738 passed 3726 unit cases, types, native checks, 17 synthetic RAM PostgreSQL scenarios and compilation. Its dependency audit failed with two moderate affected package entries. The combined Chromium installation exceeded its 300-second budget and received SIGTERM; no current-head UI case ran. The precise infrastructure cause of that earlier timeout was not established.

Vitest 4.1.12 patches [GHSA-qxg6-89mg-rqv8](https://github.com/advisories/GHSA-qxg6-89mg-rqv8) and [GHSA-xp26-3454-mjgp](https://github.com/advisories/GHSA-xp26-3454-mjgp). The first fresh audit after that patch uncovered new Next advisories [GHSA-2464-fhr4-w9xw](https://github.com/advisories/GHSA-2464-fhr4-w9xw) and [GHSA-p3m5-59mp-jv5r](https://github.com/advisories/GHSA-p3m5-59mp-jv5r), both patched in Next 15.5.28. The existing Sharp 0.35.5 override already meets the image-optimization advisory workaround; the audit finding is not evidence of an exploitable production incident. The Next patch was independently reviewed before adoption.

The manifest and lock retain all 581 package placements. Exactly the root and 18 Vitest/Next cohort placements change; 562 other package records, Sharp 0.35.5 and Playwright 1.61.1 remain unchanged. Official registry metadata supplies the exact cohort versions, integrity values and dependency edges. A narrowly pinned full inverse preserves the immutable C63 historical contract; current installed-version coherence checks use the real patched versions. Ten new cases cover installed packages and reject stale versions, foreign edges, integrity/origin changes, added or removed records and unrelated metadata changes.

The locked Playwright CLI now runs install-deps chromium with a 300-second limit, then install --only-shell chromium with a 240-second limit and a shared 540-second work budget. The per-download idle limit is 60 seconds. The browser workflow step allows ten minutes for work and bounded cleanup; the quality job stays at twenty minutes. The helper makes one attempt per phase, without audit exemptions; Playwright retains its standard internal transfer/mirror behavior. On failure, the owned Linux process group receives TERM, then KILL when necessary. Cleanup requires direct-child close and disappearance of that terminated group; processes that create a separate session are outside this scope. Stream errors and excessive output fail closed. Public receipts expose phase, time, status and cleanup facts without raw environment, URLs or stderr.

The default headless Playwright configuration uses its bundled headless shell, as documented in [Playwright browsers](https://playwright.dev/docs/browsers). The six existing PL/EN route and design cases, assertions, retries=0, network guards and source-bound receipt prerequisites are unchanged.

Restoring the three historical files to their exact committed Git bytes changed no published content or oracle. The final C63-only retest passed all ten cases with zero skips and strict C69 capture (four records, one worker epoch, zero network/DB denials); the already-green new ten cases were not repeated. Native C2 passed 6/6, and TypeScript passed. These are 20 distinct focused TS cases across the stated captures, not a single combined 20-case green run. All failed captures remain recorded.

Exact-head hosted CI is recorded in the PR checks and root evidence. This committed report describes the candidate before publication and does not predeclare a future CI result.
